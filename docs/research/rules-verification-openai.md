## What rules.md is missing (would change a GPT rewrite)

1. **`phase` round-tripping whenever preambles are prompted.** [O3]: "Missing or dropped `phase` can cause preambles to be treated as final answers". [O15]: "Correctly preserving `phase` on assistant items is required for `gpt-5.3-codex`". [O7] says the same for GPT-5.5. G10 and the gpt-5.3-codex fix should add a Settings Note: "round-trip `phase` (`commentary` / `final_answer`) or use `previous_response_id`".
2. **GPT-6 Astra autonomy specifics** [O4]: "The user should be approving a concrete, reviewable result". "Do not introduce unsolicited warnings, disclaimers, approval flows, or safety/compliance checklists due to hypothetical risk." Ask it to "name and link to the exact SKILL.md file … quote the relevant instruction". When a skill rewrites a GPT-6 prompt, S11 ("ask") and S16 ("confirm") should be weighed against these, since Astra already over-asks.
3. **Pro mode replaces "generate several candidates / think harder" prompt text.** [O6]: "You do not need to ask the model to "use pro mode," "think harder," or generate several candidate answers." Use `reasoning.mode: "pro"` on GPT-5.6 and GPT-6. This calls for a new Settings Notes row: the symptom is best-of-N or self-consistency pleas.
4. **Tone as concrete writing choices, not labels** [O5]: "Broad labels such as "friendly" or "empathetic" can be ambiguous. Describe the writing choices that define your product's tone". Also: "define both personality and collaboration style … Keep both short". No G rule rewrites "be friendly".
5. **Blanket language rules** [O5]: "Avoid blanket language rules such as "always respond in the user's language" unless that is truly the product requirement. Specify the intended output language and when it should change."
